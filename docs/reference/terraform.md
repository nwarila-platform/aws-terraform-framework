# Terraform Reference

This file is overwritten by `terraform-docs` on every PR via the
`docs-diff` gate. Do not edit by hand between the markers below.

## Interface-owned security-group rules

Rule resource keys use the declaring security-group name plus a content identity:
direction, lowercased protocol spelling, port range, destination kind, and
destination value. The readable values are sanitized and followed by a short
digest of the full identity. Rule descriptions do not affect identity.

The framework leaves AWS-owned rule-shape and duplicate-permission semantics to
AWS. The organizational exception is all-protocol scope: `-1`, its zero-padded
numeric equivalents, and `all` in any letter case require null ports because
EC2 ignores any supplied range and opens every port. Exact duplicate rules still
fail at plan time because their content-derived keys collide in Terraform's
object comprehension. Inserting or removing any other rule does not re-key
unrelated rules. Rule resources omit the `Name` tag so a valid interface group
name cannot generate a tag value beyond AWS's length limit. The `Environment`
tag and deployment-metadata tag values are bounded to 256 characters.

## Interface-owned security groups

Each interface can declare exactly one framework-created group, named
`<hostname>-eni-<interface index>-sg`, and the framework attaches it only to
that interface. This is deliberate. Security groups shared across systems or
interfaces belong outside the framework and are referenced by ID through
`security_groups`.

`null` and `[]` have different meanings for `ingress` and `egress`. Paired
`null` values create no interface-owned group. Non-null lists create the group;
`[]` means the created group has no rules in that direction. The group's
description is set only when the group is created, and later description edits
are ignored to avoid replacement.

Network-interface identity is positional. Appending an interface is safe, but
inserting or reordering interfaces re-keys every later ENI and replaces its
interface-owned group and rules. A future stable-key option can be added without
changing existing position-derived identities.

Every ENI is launched on network card 0 while `device_index` continues to match
the interface's list position. This supports multiple ENIs on the common
single-network-card instance types. The framework does not currently expose
placement across multiple physical network cards.

The pinned AWS provider deprecates the `aws_instance.network_interface` block.
The framework still needs its launch-time attachment behavior to avoid creation
of an unwanted default ENI. An internal migration to
`primary_network_interface` plus `aws_network_interface_attachment` is required
before adopting a provider release that removes the block.

## AWS security-group quotas

The framework does not impose rule, attachment, or group-count caps because AWS
quotas vary by account. The operative ceilings verified for the target account
are 60 ingress rules and 60 egress rules per security group (counted
separately), 5 security groups per network interface, and 2,500 security groups
per VPC.

These are adjustable quotas rather than hard framework limits. Operators MUST
check the target account and Region under **Amazon Virtual Private Cloud (Amazon
VPC)** in the AWS Service Quotas console, or with
`aws service-quotas list-service-quotas --service-code vpc`, before planning a
deployment near a ceiling.
